## Builds

**`foxxycode serve`** is the only long-running command: it starts every subsystem **`config.yaml`** enables (**`httpserver.enable`**, default true; **`gateways.telegram.enable`**; **`gateways.pachca.enable`**; **`swarm.enable`**; **`scheduler.enable`**) over one session manager. A subsystem enabled but not compiled in is a startup error naming the tag. Run **`make build TAGS=http`** for the HTTP surface only (REST and **`/docs`**, no **npm**). Run **`make build TAGS=cli`** for the interactive console (**bare `foxxycode`** on a terminal; see **`docs/surfaces/console.md`**). Run **`make build TAGS="http ui"`** to link the embedded SPA (**Makefile** runs **ui-build** before **go build**). Recommended full image matches **`Dockerfile`** (**`make build TAGS="http ui scheduler memory cli browser gateway swarm"`**). Default **`make build`** omits HTTPServer, scheduler, and memory to keep dependency surface lean.
Run **`make deb`** / **`make rpm`** for the Linux packages (**`PKG_ARCHS`**, **`PKG_TAGS`**, **`DIST_DIR`** knobs; nfpm is fetched on demand) and **`make brew VERSION=X.Y.Z`** to render the Homebrew cask for a published release. CI builds the Linux packages on every pull request.

Primary conversational surface for bundled UI lives at **`POST /v1/responses`** with **`stream:true`**. Prefer it over **`POST /v1/chat/completions`** when shipping FoxxyCode-hosted experiences.

Swagger lives at **`/docs/`**, OpenAPI YAML at **`/openapi.yaml`**.

## Pre-commit gate

A git **`pre-commit`** hook runs the linter before every commit, so nothing lands with lint errors. It is the single enforcement point for humans and coding agents alike. Tests are **opt-in** on commit: the express run (**`make test`**) belongs before the push; CI runs the per-combination tag matrix (**`make test-matrix`**) and race detector (**`make test-race`**). Two groups run on their own: **`make test-cache`** (the **`features/prompt_cache_*.feature`** specs and the **`TestPromptCache*`** tests, part of `make test`: what each request sends the provider, byte for byte across a session - run it when a change touches the system prompt, the rules, the history or the send boundary) and **`make test-perf`** (the benchmarks of the **`perf_test.go`** files, never part of `make test`: timings and the context a session costs, as token metrics).

- Enable once per clone: **`make hooks`** (sets **`core.hooksPath=.githooks`**; this is local config and is not committed, so every clone runs it once).
- On commit, **`.githooks/pre-commit`** calls **`scripts/checks.sh`**, which runs **`make lint`** by default. Commits touching only non-code files (docs, etc.) skip the gate.
- Scope knobs: **`FOXXYCODE_HOOK_TESTS=fast`** also runs a quick **`go test ./...`**, **`FOXXYCODE_HOOK_TESTS=full`** the whole matrix; **`FOXXYCODE_HOOK_LINT=0`** skips the linter; **`FOXXYCODE_HOOK_SKIP=1`** bypasses everything.
- Emergency bypass for a single commit: **`git commit --no-verify`**.
- Both gates compile the **host** platform only. Changing a file behind **`//go:build windows`**, or a signature it shares with the rest of the tree, needs **`make check-windows`** (cross-build plus **`go vet`** over every non-**`ui`** tag combination, test files included) and **`make lint-windows`**. CI runs both, and additionally runs **`go test`** on a real **`windows-latest`** runner for **`internal/platform`**, **`internal/bgtask`**, **`internal/tools/shell`**, **`internal/update`**, **`internal/hooks`**, **`internal/rules`** and the console TUI (**`external/cli`**, `-tags=cli`). In the Linux test matrix the `cli` job drives the console through a real pty (**`examples/cli/cli_e2e_startup.py`**), and the `gateway` job builds the gateway binary and runs **`examples/gateway/tg_e2e_offline.sh`**: the real **`foxxycode serve`** against the fake Bot API and the scripted model of **`cmd/tgfake`**, no Telegram and no LLM.
- On Windows the hook runs under the bash that ships with Git for Windows; no extra setup. **`FOXXYCODE_HOOK_TESTS`** takes **`fast`** (**`go test ./...`**), **`full`** (**`make test`**, the express run) or **`matrix`** (**`make test-matrix`**, every tag combination — what CI runs). **`full`** and **`matrix`** go through **`ui-build`**, which is known to fail on some Windows setups — **`fast`** is the practical opt-in there.

## Documentation contract

The documentation is the tree under **`docs/`**, mapped by **`docs/nav.yaml`**: `getting-started/`, `surfaces/`, `operate/`, `features/`, `reference/`, `contributing/`, `tutorials/`, and `docs/assets/` for everything a page embeds. **`docs/plans/`** (design records, never rewritten to match a later rename) is internal and stays out of the map, so the hub and the llms files do not carry it. Anything git ignores under **`docs/`** is not documentation at all and is not walked. **`docs/README.md`** (the hub), the field tables of **`docs/reference/config.md`**, the help screens of **`docs/reference/cli.md`** and the inventory of **`docs/assets/INDEX.md`** are generated by **`internal/docsgen`** (`make docs`); **`make docs-check`** (the CI job **Documentation**, and the pre-commit hook for commits that touch the docs) fails on a stale generated block, a page missing from the map, a broken relative link or anchor, and an asset no page uses. **`llms.txt`** and **`llms-full.txt`** are **not kept in this repository**: a concatenation of every page conflicted in every branch that touched one. The website build renders them (`go run ./cmd/docsgen -publish -skip-cli`, run by `make site` / `make site-check` and by the **Website** workflow) into the checkout it publishes, where they are served at **`https://hijera.github.io/foxxy-agent/llms.txt`** and **`https://hijera.github.io/foxxy-agent/llms-full.txt`**; `.gitignore` covers the paths, so a local copy never reaches a commit. The full guide, page types included, is **`docs/contributing/documentation.md`**.

A change to FoxxyCode carries its documentation in the same pull request (workflow step 10 in **`.claude/rules/workflow.md`**): a new capability gets its page, its `nav.yaml` entry and its row in the reference of its kind (`tools.md`, `slash-commands.md`, `environment-variables.md`, `keyboard.md`); a changed behaviour updates the page that describes it (`git grep -n '<key or command>' docs/`); a web UI or console feature is shown with a screenshot of the real surface embedded on its page, Dark 1280 wide, named `<feature>-<state>-<theme>-<width>.png` under `docs/assets/<page>/`. Screenshots that only prove a pull request stay with the pull request (the orphan `screenshots` branch). A page that moves takes its address with it: there are no redirect stubs, so repair the links `make docs-check` reports. Links that leave the repository - the binary, the schema descriptions, the bundled skill - name the page on GitHub (`https://github.com/hijera/foxxy-agent/blob/main/docs/<group>/<page>.md`).

Human prose for HTTP lives in **`docs/reference/http-api.md`**. Visual spec for SPA lives in **`DESIGN.md`** (this repo root). Architectural narrative remains under **`docs/contributing/architecture.md`**.

All **code comments** plus **technical markdown authored for this repo** (including `docs/`, `DESIGN.md`, `AGENTS.md`) stay **English** unless an operator explicitly asks for another natural language.

## Agent host integrations

**`AGENTS.md`** is the repository-wide baseline, and **`CLAUDE.md`** remains its compatibility symlink. Cursor and Claude Code use paired native rule trees under **`.cursor/rules/`** and **`.claude/rules/`**. Their bodies and activation intent stay equivalent, but neither vendor tree is a universal policy format.

Codex, OpenCode, ZCode and Kimi Code use repository adapters that read **`.cursor/rules/*.mdc`**. The Cursor tree is the adapters' input as well as Cursor's native representation; it is not the conceptual owner of project policy. Run **`make test-agent-rules`** after changing an adapter or rule frontmatter.

A scoped model rule is context, not an enforcement boundary. Hooks and plugins can be untrusted, disabled, fail open or miss an opaque write, so critical trust, security and destructive-operation constraints stay in root policy, code, permissions, tests or CI.

### Codex

Codex resolves its `AGENTS.md` chain once per session, walking from the repository root down to the launch directory, so a session started at the root never discovers nested instructions later. The project hook closes the scoped-rule gap for the events and payloads it understands:

- **`.codex/hooks.json`** wires **`.codex/hooks/attach_rules.py`** to `SessionStart` and to `PreToolUse` on `apply_patch` / `Edit` / `Write`;
- session start attaches every `alwaysApply: true` rule;
- pre-tool use extracts patch headers and structured path fields, then attaches unsent scoped rules whose scalar or YAML-list `globs` match;
- the hook parses `.mdc` frontmatter directly, needs no manually maintained index and fails open.

Codex requires explicit approval for hooks and tracks it by content hash. Run **`/hooks`** once per clone and again after either hook file changes. Project-local hooks also require a trusted `.codex/` layer. The full guide and manual probes are in **`docs/contributing/codex-hooks.md`**.

### Kimi Code

Kimi Code uses the parallel **`.kimi-code/hooks/attach_rules.py`** hook for `SessionStart` and `PreToolUse` on `Edit` / `Write`. It follows the ZCode JSON-field behavior, including scalar and YAML-list `globs`, per-session deduplication and fail-open error handling. Kimi Code reads hook declarations only from the user-level **`~/.kimi-code/config.toml`**, so contributors merge the versioned **`.kimi-code/hooks.toml`** fragment into that file and start a new session; the fragment is not loaded automatically. The full guide is **`docs/contributing/kimi-code-hooks.md`**.

### OpenCode

The project plugin **`.opencode/plugins/project-rules.js`** injects always-on and active scoped rules into model requests, accepts scalar and YAML-list `globs`, and preserves active rules through compaction. When a write tool first reveals a scoped rule, the plugin rejects that call once so OpenCode retries with the rule in context. See **`docs/contributing/opencode-hooks.md`**.

### ZCode

**`.zcode/config.json`** wires **`.zcode/hooks/attach_rules.py`** to `SessionStart` and `PreToolUse` on `Edit` / `Write` / `MultiEdit` / `ApplyPatch`. The behavior matches the Codex adapter, but ZCode supplies edited paths as structured JSON fields. Configuration-file hooks run because the committed config sets `hooks.enabled: true`; there is no per-hook trust prompt. The command uses `python` rather than the Microsoft Store `python3` stub on Windows. See **`docs/contributing/zcode-hooks.md`**.

## Code review invariants

Every reviewer applies this section to changed files. Keep entries behavioral and repository-specific; formatting and lint stay in CI, where the pre-commit gate already runs **`make lint`**.

### HTTP surface

- Do not change routes, request or response shapes, or status codes in `external/httpserver/server.go` without updating `external/httpserver/openapi.go` in the same change. The served spec is what `/docs/` and generated clients consume, so drift is a silent API break. Safe path: update both, then reconcile `docs/reference/http-api.md`.

### Provider transport

- Do not add a provider request path that can bypass `providers[].proxy`. Completions, streams, model discovery, usage, OAuth/device sign-in, refresh and revoke all build through `llm.HTTPClientForProviderProxy`; a test-only explicit client may be accepted, but `nil` must return an error rather than fall back to `http.DefaultClient`. When a Settings sign-in starts before Save, apply the form's current proxy after resolving the row. Safe path: extend `features/provider_proxy.feature`, keep `TestProviderProxyGuard` green, and cover the request class through the proxy harness.

### Build tags

- Do not let a package that builds by default import one that lives behind the `http`, `ui`, `scheduler`, `memory`, or `gateway` tags. Plain `make build` must keep compiling with the lean dependency set. Safe path: put the new code behind the same tag, or invert the dependency into an interface owned by the core package.

### Project-local configuration

- Do not read, merge, or execute project-local configuration (`.foxxycode/mcp.json`, MCP server definitions, hook scripts) without routing it through `TrustGate` in `internal/mcp`. Opening an untrusted checkout must not by itself grant code execution. Safe path: gate the read on the workspace trust decision and persist the approval through `TrustStore`.
- The same holds for project-scope subagent definitions (`.agents/agents` and `.foxxycode/agents` under the workspace, or any `subagents.dirs` entry there): they load and spawn only as `subagents.project_trust` allows, a receipt in `subagents.TrustStore` is bound to the file digest, and a definition must never widen what the parent could do - `permission_mode`, `tools` and `disallowed_tools` only narrow, and the mandatory exclusions stay. Safe path: resolve the definition once, decide trust on that value with `subagents.Decide`, and derive the child's tool set with `subagents.EffectiveTools`.

### Packaging

- Do not add, rename or remove a CLI subcommand, a **`serve`** verb or a flag without updating **`packaging/man/foxxycode.1`** and **`packaging/completions/foxxycode.bash`** / **`foxxycode.zsh`** in the same change (and **`topLevelCommands`** in **`cmd/foxxycode/usage_test.go`** for a command). Every install route ships those files as the documentation of the command set - the release archive through **`install.sh`**, the Homebrew cask and **`foxxycode update`**, the packages, the formula - and nothing generates them: the test holds the commands and the `serve` verbs to **`printUsage`**, flags are kept in step by hand. Step 11 of the **paired workflow rule**.
- Do not move **`/usr/bin/foxxycode`** or add a second packaged copy of the binary. **`foxxycode update`** asks **`dpkg-query -S`** / **`rpm -qf`** who owns the executable it is about to replace, and a packaged file that no database claims would be silently overwritten. Safe path: keep the single **`contents`** entry in **`packaging/nfpm.yaml`**.
- Keep the packaged service an opt-in **systemd user unit** that the package installs and never enables. Do not add a system service, a system account or files under **`/etc`**, and do not enable, start or disable the unit from a maintainer script. FoxxyCode's state is per-user under **`~/.foxxycode`**, and each user decides with **`foxxycode serve install`** / **`foxxycode serve uninstall`**. The unit is rendered by **`serve.PackagedUnitFile()`**: change the renderer and regenerate **`packaging/systemd/foxxycode.service`**, never the file alone.
- Do not add a file to the release **`.tar.gz`** layout without checking the Homebrew cask: **`packaging/homebrew/foxxycode.rb.tmpl`** links artefacts out of that archive by name.
- Do not move the man page or the completions inside the repository without updating **`packaging/homebrew/foxxycode-formula.rb.tmpl`**. The formula installs them from their source paths, and a from-source build is the only packaging route that reads the tree rather than a staged archive. Its **`test do`** block is coupled the same way: it asserts on the output of **`foxxycode -v`**, **`foxxycode sessions list`** (the **`SESSION_ID`** header) and **`foxxycode skills list`** (the **`Search roots:`** line), and once the formula is in homebrew/core those strings are checked by Homebrew's CI, not ours.
- Do not conflate the two Homebrew artefacts. The **cask** installs prebuilt macOS archives and is upgraded with **`brew upgrade --cask foxxycode`** out of a **`Caskroom`**; the **formula** builds from source and is upgraded with **`brew upgrade foxxycode`** out of a **`Cellar`**. **`internal/update`** reads which of the two owns the running executable off its path, so a change to that detection has to keep both hints correct - the wrong flag fails on the user's machine.

### Documentation

- Do not add a user-visible capability, change what a documentation page describes, or add a tool, a slash command, an environment variable or a key without carrying the change into **`docs/`** in the same pull request: the page under `features/`, `surfaces/` or `operate/`, its entry in **`docs/nav.yaml`**, the reference of its kind, a screenshot on the page when the change is visible in the web UI or the console. **`make docs-check`** catches a missing map entry, a broken link and an unused asset, but it cannot tell that a paragraph went stale - that is what the review is for. Safe path: `git grep -n '<key or command>' docs/` before the change, update every hit, then `make docs`.
- Do not commit screenshots that no page references, and do not put pull request evidence under **`docs/assets/`**. Do not delete or move a page without repairing the links `make docs-check` reports.
- Do not edit inside a `<!-- docsgen:*:start -->` block by hand; change the source (`nav.yaml`, the schema description, `printUsage`) and run **`make docs`**.

### Embedded UI

- Do not treat a UI change as complete when only `external/ui/src/` moved. The binary serves `go:embed` assets, so unrebuilt sources ship the previous SPA. Safe path: run `make build TAGS="http ui"` and include the regenerated assets in the change.

### Upstream ports

- Do not take the upstream side of a site marked `// fork(<id>)`, and do not take an upstream hunk that undoes one without a conflict. Each marker names an entry of **`.claude/rules/upstream-divergences.md`**: a decision the owner made to keep FoxxyCode's behaviour, with the guard tests that pin it and what to do when upstream changes that place again. **`internal/forkguard`** fails when a marker, a guard test or a registry row goes missing. Safe path: follow the entry, and ask the owner before retiring it.

### Text encoding

- Do not add a second decoder for workspace file bytes. `internal/textenc` is the one place an encoding is decided, and the file tools reach it through `decodeText` in `internal/tools/fs`. A local `utf8.Valid` check or a hardcoded charmap makes Windows-1251 sources unreadable in one tool while another reads them fine. Safe path: call `textenc.Decode` and carry the returned `Encoding` back into `Encode` when rewriting the file.

## HTTP API development flow

When changing behavior for the OpenAI-compatible HTTP gateway or bundled UI:

- Add or update tests first (red), then implement (green). The **happy path** of a feature (and a bug's reproduction) is a Gherkin spec in the repo-root **`features/`** directory, run by a godog harness (e.g. `external/httpserver/bdd_*_test.go`, pointing `Options.Paths` at `../../features/<name>.feature`); **edge/error cases go in ordinary unit tests**, not `features/`.
- If the external HTTP surface changes, update `external/httpserver/openapi.go` so the served OpenAPI matches handlers in `external/httpserver/server.go`.
- Keep `docs/reference/http-api.md` aligned with the live behavior.
- For UI changes, update sources under **`external/ui/src/`** and rebuild embedded assets via **`make build TAGS="http ui"`** (runs **npm** via **make ui-build**).
- **Every** UI edit in a PR ships with a screenshot of the surface it changed (before/after when the surface already existed) — see step 5 of **`.claude/rules/workflow.md`**. If a surface cannot be captured, say so in the PR instead of omitting it.
- **`internal/config/config.schema.json`** is embedded into the binary (`go:embed` in **`internal/config/schema.go`**: it is what **`-t` / `--test-config`** validates a file against, and its `description` strings are the `doc:` lines of that report). It also leaves this repository: **`docs/config.schema.json`** is a byte-for-byte republication of it, served by GitHub Pages at the address FoxxyCode writes as a modeline into every config it saves. Touching the YAML config surface means **`make site-schema`** (and **`make site-schema-check`** to see whether the published copy is stale; **`TestPublishedSchemaMatchesTheEmbeddedOne`** fails on drift). Hold the publish until the release when a key was renamed or removed: the schema sets **`additionalProperties: false`**, so the new file marks the old key as an error in configs already on disk. Full step: the **paired workflow rule**.
- Do not add, rename or remove a CLI subcommand, a **`serve`** verb or a flag without updating **`packaging/man/foxxycode.1`** and **`packaging/completions/foxxycode.bash`** / **`foxxycode.zsh`** in the same change (and **`topLevelCommands`** in **`cmd/foxxycode/usage_test.go`** for a command). Every install route ships those files as the documentation of the command set - the release archive, the packages, the Homebrew formula - and nothing generates them: the test holds the commands and the `serve` verbs to **`printUsage`**, flags are kept in step by hand. Step 11 of the **paired workflow rule**.
- Run the express regression `make test`, then `make lint`. The tag matrix (`make test-matrix`) is CI's job — run it locally only when a build-tag boundary moved.

## UI sources (`external/ui/`)

**`DESIGN.md`** is the contract for layout, tokens, and SPA component behavior. After changing **`external/ui/src/`**, rebuild embedded assets with **`make build TAGS="http ui"`** before relying on **`go:embed`**.

The composer exposes **`Mode`** (**`agent`** / **`plan`** / **`docs`** / **`ask`** / **`debug`**) and a separate **`Model`** YAML backend selector (**`metadata.model`**; list rows with **`owned_by`** other than **`foxxycode`** from **`GET /v1/models`**). New chats use the valid **`foxxycode_llm_model`** cookie, otherwise the alphabetically first configured model; opening a session restores its saved model. Parallel **`POST /v1/responses`** per session, **Stop** (**cancel** + partial assistant persistence), and transcript merge after **`GET .../messages`** are specified in **`DESIGN.md`** (**Multi-session streaming and Stop**) and **`docs/surfaces/web-ui.md`**.

**`MarkdownLineEditor`** (`external/ui/src/ui/markdown/`) is the shared markdown body editor (line gutter, wrap-aware numbering, active-line highlight, content-driven height). Used in the plan document card and scheduler job body. Visual and behaviour contract: **`DESIGN.md`** (**Markdown line editor**, **Plan mode plan document card**); functional checklist: **`docs/surfaces/web-ui.md`**.

**UI localization** lives in **`external/ui/src/ui/i18n/`** (**`translate`/`t`**, **`I18nProvider`** + **`useT()`**). **`locales.ts`** is the single registry that connects each supported locale to its picker label and dictionary; English and Russian ship today. Add a locale by adding its dictionary and one registry entry — picker options, locale validation, bootstrap, and parity coverage derive from that registry. In Russian copy the adjective for agent/agentic is **агентный**, never **агентский**; a spawned agent is a **субагент**, never **сабагент**; a git worktree stays **worktree**, never **рабочее дерево** (the **paired Russian wording rule** - [Cursor](.cursor/rules/russian-wording.mdc), [Claude Code](.claude/rules/russian-wording.md) - held by **`ruWording.test.ts`**; `git grep -n -i 'агентск'` and `git grep -n -i 'сабагент'` find nothing but the rules that forbid them). When user-facing copy is added or changed on a localized surface, add the key to **every registered dictionary in the same change**; **`messagesParity.test.ts`** enforces key and interpolation-token parity. Counted copy ("N tasks") goes through **`translatePlural`** / **`tp(key, count)`** with one entry per CLDR category (**`key.one`** / **`key.few`** / **`key.many`** / **`key.other`**) so each language declines by number; a locale must carry exactly the categories its own **`Intl.PluralRules`** produces. **`main.tsx`** bootstraps locale (**`?lang=` > cookie > `navigator.language`**) and wraps **`<App/>`** plus the shared confirmation provider in **`<I18nProvider>`**. The language picker is in **Settings → Appearance**, under the theme grid (**`AppearanceLanguagePicker`**); cookie **`foxxycode_ui_lang`** mirrors **`foxxycode_ui_theme`** (client-side only, no config save). Appearance, Settings, shared destructive confirmation dialogs, and the conversation surfaces (nav, hero, composer, messages, prompts, plan card, History, scheduler, background tasks, env banner) and the swarm screen (including the topology graph) are translated. Visual contract: **`DESIGN.md`** (**Localization and language**); functional checklist: **`docs/surfaces/web-ui.md`**.
