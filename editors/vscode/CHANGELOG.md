# Изменения в расширении FoxxyCode для VS Code

## Unreleased — 2026-09-07

**Карточка списка задач больше не превращается в обычную карточку инструмента.**
Строки `foxxycode_todo_item_update` и `foxxycode_todo_plan_replace` после обновления
транскрипта (возврат в окно, ответ на запрос разрешения, обрыв и переподключение живого
потока) и в ветках сессии иногда теряли оформление плана и показывались как обычный вызов
инструмента с сырым JSON и строкой «updated item N». Снимок плана терялся при перезаписи
метаданных вызова на диске, не копировался в ветку и не переносился из уже показанной
строки. Теперь сервер сохраняет снимок при завершении вызова в любом порядке записи и
забирает его в ветку, интерфейс не забывает уже полученный план, если сервер его не
прислал, а без снимка рисует карточку из аргументов самого вызова. Отдельно починен
случай моделей NeuralDeep (kimi-k2.6 и другие): они отдают id вызовов вида
`functions.foxxycode_todo_plan_replace:0`, а двоеточие недопустимо в имени папки на
Windows, поэтому для таких вызовов на диск не попадали ни аргументы, ни результат, ни
снимок плана — теперь папка вызова получает безопасное имя, а старые папки читаются как
прежде.

## 0.2.51 — 2026-09-07

**«Добавить в FoxxyCode» из контекстного меню.**
У файлов в Explorer (в том числе при множественном выборе), у вкладки редактора и в самом
редакторе появился пункт **Add to FoxxyCode**: выбранные файлы вставляются в поле ввода чата
как `@`-упоминания с полным путём относительно рабочей области. Если панель FoxxyCode ещё
не открыта, она откроется сама, а упоминания появятся, как только загрузится интерфейс.
Раньше единственным способом было перетаскивание с зажатым Shift; оно по-прежнему работает.

**Чтение вывода терминала, открытого до запуска расширения.**
Раньше агент видел только вывод команд, запущенных после старта расширения через shell
integration VS Code. Новая настройка **Terminal clipboard capture** (по умолчанию
выключена) дополнительно снимает видимый буфер активного терминала через буфер обмена
(выделить всё → скопировать → восстановить), как это делает cline: при смене активного
терминала и при показе панели FoxxyCode, не чаще раза в две секунды. Буфер обмена
восстанавливается сразу после снимка, но менеджеры истории буфера его запишут — поэтому
включать нужно осознанно.

**Команда «Verify Binary».**
В палитре команд появилась **FoxxyCode: Verify Binary**, а в описании настройки *Binary
path* — ссылка **Verify binary**. Проверка запускает бинарник (свой или встроенный),
показывает его версию и предупреждает, если это lean-сборка без HTTP/UI, или если файл не
найден и не запускается. Результат также пишется в канал вывода FoxxyCode.

**Понятная ошибка, когда фиксированный порт занят.**
Если в настройке *Port* указан конкретный порт и его держит другой процесс (второе окно
VS Code, ещё не завершившийся бэкенд после обновления расширения), расширение ждёт до
трёх секунд, а затем сообщает «Port N is already in use by another process» с кнопкой
открытия настроек — вместо прежнего общего «процесс завершился до готовности».

**Собственный режим встраивания `embed=vscode`.**
Интерфейс в панели теперь знает, что он внутри VS Code, а не в JCEF-окне IntelliJ.
Внешний вид (плоское поле ввода без стеклянного ореола) не изменился, но обходные
решения для старого Chromium 104 из IntelliJ больше не применяются в VS Code, и длинные
диалоги прокручиваются так же легко, как в браузере.
